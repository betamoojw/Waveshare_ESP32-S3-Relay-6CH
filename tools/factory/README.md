# Factory Tooling

These commands implement the application-facing production station flow. They
consume a complete release package from `tools/release/create_release_package.py`
and communicate with the device over its physical serial service interface.

## Security Boundary

The tools never burn eFuses and never accept secure-boot or flash-encryption
private keys. `flash_firmware.py` installs only the four digest-verified release
artifacts. An approved secure station must provision irreversible ESP32-S3
security state; `verify_device.py` then obtains read-only `espefuse` evidence or
consumes the station's JSON report.

Administrator credentials are held in a restricted file generated by
`generate_credentials.py`. The password is sent only to `provision-web` over
the local serial session. It is never printed, written to factory work files,
or included in the production record.

The trusted Secure Boot public key is a station trust-store input and must not
be taken from the release package being verified. Both `bootloader.bin` and
`firmware.bin` are verified with this key before any flash write.

## Setup

```text
python -m pip install -r tools/factory/requirements.txt
```

Install Espressif `esptool`/`espefuse` in the station environment or pass the
path to each Python entry point with `--esptool` and `--espefuse`.

## Complete Flow

Generate a protected credential input outside the repository:

```text
python tools/factory/generate_credentials.py \
  --output C:/protected/station/SA2608240001-credentials.json
```

Run the controlled flow with an approved release package:

```text
python tools/factory/provision.py \
  --release release \
  --serial SA2608240001 \
  --hardware-revision HW-A01 \
  --batch 42 \
  --knx-individual-address 1.1.42 \
  --credentials C:/protected/station/SA2608240001-credentials.json \
  --secure-boot-public-key C:/protected/station/production-secure-boot-public.pem \
  --port COM5 \
  --station-id STATION-01 \
  --operator-id OPERATOR-01
```

The command verifies release digests before flashing, derives the LittleFS
offset from `partitions.bin`, pauses for the approved security operation,
provisions identity and Web security through physical service mode, verifies
the rebooted unit and safe relay state, and atomically creates
`production-records/<serial>.json`.

Each stage is independently usable:

```text
python tools/factory/generate_device_id.py --help
python tools/factory/generate_credentials.py --help
python tools/factory/flash_firmware.py --help
python tools/factory/verify_device.py --help
python tools/factory/export_device_record.py --help
```

Use `--security-report` for an audited station export. Use
`--firmware-already-flashed` only when the fixture has independently associated
the exact release digest with the device. `--unattended` removes prompts but
does not bypass physical service authorization or security verification.

Run offline tests with:

```text
python -m unittest discover -s tools/factory -p "test_*.py" -v
```
